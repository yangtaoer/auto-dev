# 网络发令：账号与动态岗位

来源：用户于 2026-09-18 补充的测试业务说明。事实状态：用户确认，尚未执行浏览器登录验证。

## NC-ACCOUNT-001：账号命名

- 网络发令账号基本使用用户姓名全拼，少数账号在全拼后带数字。
- 必须使用用户给定或环境中确认的完整账号；不凭姓名推算后直接登录，不漏掉数字后缀。
- 用户提供了测试环境共用口令约定，实际口令仅保存在本机凭据条目 `network-command-test-shared`。不能把该约定扩展为生产环境口令，也不据此自动修改账号密码。
- 本机凭据位置见 [维护说明](maintenance.md)。

## NC-SHIFT-001：当前岗位不固定绑定账号

- 网络发令允许在交接班时选择职位，因此值长、正值、副值等当前岗位并非账号的永久属性。
- 用户说明：测试环境不交接班时，本次提供的岗位安排不会因交接班而改变。
- 普通回归不主动交接班、不切换岗位。开测前核对界面显示的当前岗位、单位和主配范围；用户给出的对应关系是本轮初始参考，不代替实际状态检查。
- 若岗位与档案不同，记录当前状态并调整测试角色分配；不要直接判定业务缺陷，也不要仅为符合档案擅自交接班。
- 只有专门验证交接班或用户另有要求时，才把交接班列入会改变岗位状态的测试步骤。

## 建议用例（待实现，非已通过结果）

- 完整账号（含可能的数字后缀）与登录后身份一致。
- 多角色同时在线时会话、单位、岗位互不串用。
- 测试开始和结束记录岗位；未测试交接班的场景不改变班次。
- 验证权限时同时记录账号、岗位、单位、管辖范围和单据状态，不能仅依据账号名称。
