## SC-TICKET-LOSS-ROOT-001：本地代码证据与隔离验证

代码核对范围：本地四川省调 `dcsd-direct-ui-sichuan` 委托票脚本 `src/main/resources/META-INF/resources/tbp_config/runtime/module/direct/dd/forms/wtcz_ylzxzb.form.js`，普通票脚本有同类逻辑；本地平台依赖为 `eomp-cloud-fvengine:1.0.23.7`。本地版本不是现场部署版本的证明。

- 委托票 `autoSubmitFormRewrite()` 在操作项目 `cznr` 为空时执行 `delete arr[i]`，从提交数组跳过该行，因此四个空白新增行没有入库。单位、厂站完整不改变这一判断。
- `np_autoSave()` 在保存返回成功后调用整个表格的 `grid.accept()`；已跳过的行也被清除 `_state = added` 标记。
- 补填操作项目时，MiniUI 把这些行标成 `modified`。送审调用 `submitFormRewrite()`，按该状态提交更新。
- 平台按 `_state` 区分插入和更新。`modified` 走按 `mxid` 的 UPDATE；四个明细主键对应的记录并不存在，更新影响零行。批量更新没有把每行影响数为零判为失败，表单接口仍返回更新成功。
- 送审前 `setZlxh()` 按页面六行重新编号，已存在的末行能更新到序号 6，因此可出现仅显示编号 1、6 的断号结果。

代理使用真实前端保存函数、MiniUI 编码和行状态函数，配合内存模拟后端更新规则完成隔离验证：补填前跨过自动保存的用例仅存储第 1、6 条，页面仍有六条且返回成功；第一次自动保存前全部填齐的对照用例存储六条。该验证没有访问业务库，不等同于业务环境端到端回归。
