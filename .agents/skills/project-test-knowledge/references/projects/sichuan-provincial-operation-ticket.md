## SC-TICKET-LOSS-ROOT-001：本地代码证据与隔离验证

代码核对范围：本地四川省调 `dcsd-direct-ui-sichuan` 委托票脚本 `src/main/resources/META-INF/resources/tbp_config/runtime/module/direct/dd/forms/wtcz_ylzxzb.form.js`，普通票脚本有同类逻辑；本地平台依赖为 `eomp-cloud-fvengine:1.0.23.7`。本地版本不是现场部署版本的证明。

- 委托票 `autoSubmitFormRewrite()` 在操作项目 `cznr` 为空时执行 `delete arr[i]`，从提交数组跳过该行，因此四个空白新增行没有入库。单位、厂站完整不改变这一判断。
- `np_autoSave()` 在保存返回成功后调用整个表格的 `grid.accept()`；已跳过的行也被清除 `_state = added` 标记。
- 补填操作项目时，MiniUI 把这些行标成 `modified`。送审调用 `submitFormRewrite()`，按该状态提交更新。
- 平台按 `_state` 区分插入和更新。`modified` 走按 `mxid` 的 UPDATE；四个明细主键对应的记录并不存在，更新影响零行。批量更新没有把每行影响数为零判为失败，表单接口仍返回更新成功。
- 送审前 `setZlxh()` 按页面六行重新编号，已存在的末行能更新到序号 6，因此可出现仅显示编号 1、6 的断号结果。

代理使用真实前端保存函数、MiniUI 编码和行状态函数，配合内存模拟后端更新规则完成隔离验证：补填前跨过自动保存的用例仅存储第 1、6 条，页面仍有六条且返回成功；第一次自动保存前全部填齐的对照用例存储六条。该验证没有访问业务库，不等同于业务环境端到端回归。

## SC-TICKET-AK-LOSS-001：追加安控误清理原票行的独立风险

来源：2026-10-26 用户反馈正令“追加安控”后丢指令，明确丢失的是“原票已有指令”，对是否已经保存并重新打开表示“暂不确定”。不能把“已有”直接记为“已经入库”，也未取得现场票号、环境或丢行前字段快照。

本次核对 UI HEAD `1aa842990e8f430754835922c1283ead266e9aab`，刷新后的 origin/dev 为 `5a5475509dae4aa9cc08dbcf5c99e314afb663af`；普通和委托正令脚本在二者间无差异。此前保存状态修复 `e0e8840b` 已包含于 origin/dev，追加前清理逻辑没有被该修复更改。普通正令该段代码可追溯至 `3df868187`，2023-03-21。

- 追加调用路径为 `akAppend()` → 解析安控数据 → `loadCzpByWord(..., true, ids)`。后者先按 `!row.zlxh || (row.zlxh == "▲" && !row.orderkind)` 找行，再执行 `grid.removeRows(rows, false)`；注释写“清理默认空行”，实际上没有检查操作内容、业务字段或行是否已经入库。
- 普通正令位置为 `direct/forms/zlzxzb.form.js` 的 `loadCzpByWord()`（本次行 9178—9184）；委托正令同类代码位于 `direct/dd/forms/wtcz_zlzxzb.form.js`（本次行 6368—6374）。普通、委托预令也有相同清理条件，仅做了代码核对，未把它们计入本轮 14 组执行验证。
- 原普通指令内容、单位、厂站完整，但底层 zlxh 为空时，也会被删除。注释指令 orderkind 为 `2` 时，drawcell 可直接显示“▲”，不保证底层 zlxh 有值，因此页面看起来正常的注释也可能命中 `!row.zlxh`。已有“▲”但类型缺失的行同样被清理。
- 项目真实 MiniUI 的 `removeRows(..., false)` 会调用 removeRange/removeAt/_setRemoved，将已入库行标为 removed；false 不能理解为不生成删除变更。下一次自动保存或编辑保存会把该行作为删除记录提交。
- 清理发生在追加位置确认之前；未选择行、选择“当前行后”后提示“请先选中一行”退出时，原行也已经进入删除缓存。位置确认框的“取消”表示追加到票尾，不是取消整个追加操作。
- 与 SC-TICKET-LOSS-ROOT-001 区别：上次是未入库的新增行被错误 accept，补填后误走 UPDATE；此处是已有行被追加入口主动 remove，随后提交 DELETE。保存成功后只确认提交行的修复无法识别这种误删。
