# 四川省调 PC 厂站复诵一致性与脚本规则差异

项目键：`sichuan-provincial-network-command`；修订日期：2026-10-27（Asia/Shanghai）。适用于四川省调 PC 普通票复诵，不推及其他地市或 APP。

## SC-REPEAT-COMPARE-001：用户反馈与输入证据

用户提供逐2026100286主从表 SQL 导出及厂站复诵截图：第4条资阳站指令，数字1、2、1均显示绿色，却提示“复诵内容与下令内容不一致”。用户明确表示测试环境原样执行两份 SQL，并采用相同的填写复诵方式，可以通过；现场为 Chrome 或 Edge 普通模式。用户称配置“应该是0”，这是待实测信息，不等同于已读取报错窗口实际 sysconfig.czfsfs。

代理只解析附件，没有执行 SQL 或连接业务库。导出有21条明细（1条注释、20条普通指令）；第4条对应总序5。该条原文“正常启用”与逗号之间有一个普通空格 U+0020，索引21（从0开始），没有检测到其他空白或控制字符。导出记录已是 ISDHL=1、FLMODE_STATE=8 的后续电话令结束状态，不是报错窗口当时的完整运行时快照；不保存导出票据的全部内容、操作人或完整附件到知识库。

## SC-REPEAT-RULES-001：同名脚本对配置0的解释不同

本地两个可用资源都叫 `META-INF/resources/direct/forms/flmodemxsr.js`，但校验分支存在明确差异：

| 配置 czfsfs | 四川 UI 当前源码 | 本地通用 UI 2.0.0-SNAPSHOT 包 |
| --- | --- | --- |
| 0 / 默认分支 | 填写与拼接必须都正确（AND） | 有填写项时任一种正确即可（OR）；无填写项时要求拼接正确 |
| 1 | 只校验拼接 | 只校验拼接 |
| 2 | 只校验填写 | 只校验填写 |
| 3 | 没有显式分支，落入默认 AND | 显式要求填写、拼接都正确 |

四川来源：`dcsd-direct-ui-sichuan` 的 `direct/forms/flmodemxsr.js`，原始文件 SHA256 前16位 `a07465b43a58f774`。通用来源：本机 Maven `dcsd-direct-ui:2.0.0-SNAPSHOT` JAR 中同路径资源，SHA256 前16位 `4fe59eb1be1064e9`。这些是本地资源证据，不是已经读取了现场或测试部署文件；同名资源的实际加载版本、覆盖顺序、缓存仍需核对。

以配置0为前提，数字填写完全正确而拼接结果为空：四川分支判失败，通用分支判成功。它能完整解释“同票同操作，一边拦截、一边通过”的机制，但不能仅凭本地包差异就断言现场与测试分别加载了哪一份。也不能只把所有 AND 替换为 OR；若后续对齐通用规则，需保留模式3的双校验、无填写项时必须拼接，以及拼接内容的归一化。

## SC-REPEAT-COMPARE-002：绿色数字与整句校验是两层

四川 cznrVali() 先还原输入框、选择框并按 sysconfig.czfsfs 校验整句，再独立为每个数字控件着色。三格全绿只说明对应数字分别正确，不保证拼接也完成或整句一致。截图的这条提示至少说明前端 flag 未通过；后台双确认失败另有“后台对比指令内容不一致”提示，不能用数字绿色推定整体验证成功。

整句填写比对使用隐藏原文值和还原 HTML 的 `.html()`。原文侧与还原侧均清除普通空白，因此不能直接归因 U+0020；还原侧没有解码 `&nbsp;` 等空格实体，若运行时出现此类实体，也可能数值全绿但整句失败。这只是已验证的潜在机制，不是已在现场 HTML 中观察到 `&nbsp;`。

## SC-REPEAT-ISOLATION-001：本机隔离验证

读取本地原始 dcsd-system-srv StrUtils 类，调用 CZNRPX_mainczpSiChuanSD、CZNRPXColor_mainczpSiChuanSD生成真实输入与着色 HTML；对照本地 dcsd-direct-srv getSichuanMx 的清理规则，执行当前四川 cznrVali()。岗位、状态与业务接口预检查使用隔离桩，业务提交回调被替换为本地结果标记，不构成业务账号走票或完整后端验证。

- Chromium 浏览器5组：当前生成内容+模式2+填写1/2/1通过；保留普通空格的对照通过；四川模式0只填数字时三个数字全绿但整句失败；填错一个数字时失败且该框红色；人工模拟静态 HTML 含 `&nbsp;` 时三个数字全绿但整句失败。
- 从两份原始源码提取模式分支，使用上述浏览器取得的相同比较值执行6组对照：模式0只有填写正确、只有拼接正确时，四川失败而通用成功；模式0两项都对或都错时一致；模式3只有一项对、两项都对时两版结果一致。这是原始条件分支执行验证，不冒称通用包完整浏览器流程验证。
- 只读采集脚本6组检查通过：与离线比较结果一致，不调用复诵/保存/发令或网络，不改页面，不输出无关配置或查询令牌。

本轮没有修改业务源码；之前追加安控/定值单修复的六份本地改动保留。没有执行附件 SQL、登录业务账号、提交业务代码或发布服务。浏览器隔离 TaskSpace 已结束，自建测试服务已停止。

## SC-REPEAT-DIAG-001：现场确认所需的最小证据

同一条票报错后保留弹框，读取该窗口实际 sysconfig.czfsfs、填写还原串、拼接还原串、校验函数及资源版本。优先核对配置0时拼接是否为空，以及现场/测试函数是否含显式模式3和“任一种正确”的 OR 分支。如果两边确实同脚本、同配置、同两个比较值，结果不应不同；应核对这些前提，而不是继续仅靠导入票据重试。

本机目录：`dcsd-springboot-sichuan/temp/ticket-repeat-analysis-20261027/`。`现场复诵只读诊断.js` 自动寻找这张票的复诵窗口，输出两套规则预测、实际脚本特征/摘要、首个差异及输入值；未找到该票时只提示切换正确窗口，不读取其他票据内容。脚本只读，不调用业务动作。摘要差异仅提示需进一步核对正文，不能单凭哈希认定根因。其余证据为 browser-results.json、rule-version-comparison.json、source-fingerprints.json；尚未取得现场实际脚本和报错时比较串，现场具体归因仍待确认。
