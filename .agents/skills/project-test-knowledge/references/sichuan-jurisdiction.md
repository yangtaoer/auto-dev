# 四川网络发令：主配管辖与业务归属

来源：用户于 2026-09-18 补充。事实状态：用户确认。
适用范围：成都，以及四川其他明确存在主配一体模式的地市网络发令。各地数据库名、单位 ID、业务字段映射不得直接复用成都值。

## SC-SCOPE-001：发令到受令的有向关系

- 管辖关系表中的 `FLORGANNAME` 表示发令单位，`SLORGANNAME` 表示受令单位。
- 对某发令单位查询出的记录表示其直接配置的受令关系；不能把列含义反过来。
- 存在三级关系，也存在两级、三级混用。测试设计不能强制所有单位都落在相同深度，也不能把某单位永远归类为只发令或只受令。
- 某单位在不同关系中的角色与其当前业务上下文有关。需要分别核对它作为某关系受令方、其他关系发令方时的权限。
- 层级可达不自动等于业务授权：不得自行把两条直接关系推导为上级可直接操作所有下级。直接、跨级与委托规则应由关系数据和具体业务实现共同确认。

## SC-SCOPE-002：票据归属与 areano

- 用户确认：操作票通过 `areano` 字段说明该票由哪个调度管辖；其他业务也有类似的归属控制。
- 不要仅凭当前用户所属单位、受令单位或显示名称判断票据归属；需要核对票据的管辖字段与该用户当前业务范围。
- `areano` 的实际值和单位 ID、区域 ID、调度标识之间如何映射，尚未由本次说明确定。不能直接断言它等于某个 `ORGANID`，也不能把它当成任意行政区划代码。
- 其他业务的字段可能不同，不能把所有业务都硬编码为 `areano`；沿该业务的列表查询、详情、操作权限和提交接口确认。

## 建议测试矩阵（待实现）

1. 直接配置的发令单位与受令单位能在正确范围内完成对应业务。
2. 不同调度管辖的票据，列表、详情、待办/提醒和写操作保持一致的数据范围。
3. 分别覆盖两级、三级，以及同一环境两者混用的实际关系。
4. 对兼具上下级关系的单位，分别验证上下行上下文，不因账号或单位名称相同串用权限。
5. 使用同类型、不同调度归属的测试票据验证隔离；具体允许/禁止操作以当前需求和项目规则为准。

成都 schema 和查询示例见 [成都档案](projects/chengdu-network-command.md)。省调虚拟单位的具体业务规则尚待用户补充，不能用“名称是否包含虚拟”来判断是否存在虚拟单位。
