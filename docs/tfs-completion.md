# TFS 完成回写规则

适用：普通研发交付、问题分析完成、最新目标分支已完整实现的复核交付，以及全部子项目成功的联合需求。

- TFS 状态：`System.State = 已解决`。
- TFS 实际交付版本：`Custom.adf4ae15-611e-4565-9f47-a9f24561efa9 = V1.0`。
- 状态、实际交付版本与交付产物/报告说明用同一次工作项 PATCH 写入；有 revision 时使用 `/rev` 乐观锁。
- 重试前读取远端：仅状态、版本和本次产物说明全部一致才跳过重复写入。状态正确但版本为空、旧值或“不适用”仍须补写。
- 必须确认响应中状态和版本符合目标，才能报告回写成功；写入失败不得伪造已完成。
- 联合需求只在全部子项目成功后统一回写；任一子项目未完成、失败或取消，都不能提前解决整张需求。
- 已有实现的复核不重复提交、创建 PR 或构建；只补齐完成回写。
- 问题分析仍不修改代码、不构建、不发版。`V1.0` 是统一的 TFS 完成登记口径，不代表产生了代码发布版本，也不代表提出人已验收。

本规则不自动批量修改历史工作项，不改变独立的人工验收与项目经验状态。
