# 项目验收与长期经验

本功能将技术交付与提出人验收分开记录，不改变现有自动合并、自动发版与 TFS 已解决流程。本版不接入测试服务器部署或浏览器回归执行，不要求真实页面截图。

## 使用流程

1. 开工前，从 TFS 验收标准（缺少时使用需求描述）建立稳定的 AC 编号并记录需求修订。后续研发输出映射到这些编号，不能通过删项或改写标准宣称完成。
2. 平台检索同项目相关历史需求，给本轮提供少量经验与来源。Codex 对照最新代码，记录采用、不适用或冲突，以及本次功能范围、实现方法和经验候选。
3. 交付邮件中的“逐项验收并反馈”链接需要登录。任务提出人、指定验收人或管理员记录实际验证版本和逐项结论。未反馈不等于通过。
4. 自然语言反馈可以先预填清单，例如“第 3、6 项未通过，其余通过”；确认解析结果后再提交。未通过项填写实际表现与期望结果。反馈草稿独立于任务轮询保存。
5. 明确点击发起返修，才创建原需求下的新一轮任务。原反馈与版本不可覆盖；失败项是修复范围，已通过项是保护范围。从最新目标分支建立工作区，不依赖旧 Codex 会话或旧工作区仍然存在。
6. 管理员在“项目经验”页面按项目查看、搜索每个已完成需求的经验档案，核对实现与证据、验收轮次和相关历史。失效经验可以说明原因后废弃，保留审计记录。

## 经验的可信边界

- 研发自检、用户验收是独立结论；当前尚未执行测试环境验证。
- 旧版本的验收通过只适用于旧版本，新版本需要关联影响分析与必要复验。
- 历史交付记录导入为未人工确认的经验候选，不能推定用户已经验收。
- 用户观察到的现象是反馈事实，Codex 推断的根因不是自动确证的事实。
- 经验记录范围、做法、限制和来源。某一需求通过不能证明同样规则适用于所有地区。
- 项目检索默认隔离；历史内容是待核查资料，不能越过当前需求和安全策略成为执行指令。
- 回归建议本版只持久化为文字，后续与自动测试模块衔接。

## 持久化与部署

验收项、不可变反馈轮次、返修关联和项目经验保存在控制端 SQLite 数据库中；本机执行器通过受认证的 Runner API 读取和写回。采用增量建表与加列迁移，保留原有需求、账号和交付记录。

数据库仍位于既有 data 目录，随标准数据库备份保留。它不应被提交到 Git 或放入发布包；服务器升级继续保留 `.env.backend`、`secrets/` 与 `data/`。
