# 任务动力核心

AutoDev 的“任务动力核心”把任务状态变成可感知的运动反馈，让用户不必只依赖状态文字判断任务正在识别、研发、构建、等待或交付。

## 研究边界

设计研究参考了 [blessonism/grok-icon-study](https://github.com/blessonism/grok-icon-study) 对“状态机、弹簧运动和角色反馈”的拆分思路。该仓库明确限定为学习参考、禁止商用和再分发，并包含第三方角色资产，因此 AutoDev 不复制其中的源码、几何数据、造型、图标或动画参数。

平台实现是独立设计：使用纯 HTML/CSS 组成机械印章形态，通过现有任务状态驱动 CSS 动画，不引入第三方运行时或素材。

## 状态映射

| 动作 | 平台状态 | 反馈意图 |
| --- | --- | --- |
| `inspect` | 项目识别、准入校验 | 扫描线与视线移动，表达正在读取和判断 |
| `poised` | 排队、等待执行器 | 低频呼吸和时钟式旋转，表达任务仍然存活 |
| `craft` | DevCore 研发、联合研发 | 快速加工、双眼交替和光标闪烁 |
| `dispatch` | 提交、截图、汇总交付 | 数据块向外传递，表达结果正在流转 |
| `forge` | 构建、自动发版 | 高频脉冲和反向扫描，表达编译与制品生成 |
| `await` | 等待合并、补充信息、人工确认 | 收窄视线与慢速呼吸，表达暂停而非卡死 |
| `complete` | 已交付 | 绿色核心和短促庆祝 |
| `blocked` | 失败、驳回 | 红色倾斜核心，保持清晰而不过度打扰 |
| `dormant` | 已取消 | 去色静止 |

## 体验与性能约束

- 动画只改变 `transform`、`opacity` 和少量滤镜，不启动常驻 JavaScript 渲染循环。
- 页面复用现有轮询结果，只更新 `data-motion`，任务状态变化时无需重建卡片。
- `prefers-reduced-motion: reduce` 下关闭循环动画，仍保留颜色和姿态差异。
- 图形标记为装饰性内容；状态文字仍是无障碍信息的唯一语义来源。
