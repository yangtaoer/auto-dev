# 研发交付产物契约

适用于所有项目、所有交付方式与旧任务策略快照；问题分析任务仍单独交付分析报告。

## 用户可见范围

- 业务系统包：本地构建的正式包，或已成功交付流水线的业务包产物页。
- SQL：新交付集中为一个文件，覆盖本需求需要的建表、初始化、迁移和适用的回退路径。单份脚本以原格式交付。多份脚本按来源合并，沿用各段用途和前置条件，合并文件将实际 SQL 保存在可选取的注释段中，按适用路径去掉段前缀执行。所有源脚本都禁止使用存储过程、匿名过程块或动态执行。
- 字段注释：新建表的每个字段以及新增或变更的字段，应在相应的表结构 SQL 中带上非空业务注释。达梦、Oracle 和 PostgreSQL 使用 `COMMENT ON COLUMN`，MySQL 可使用字段定义中的 `COMMENT`。平台会核对脚本和合并文件的各段。
- 必要配置：配置文件、配置项合并模板；密码等值使用部署环境占位符。
- 旧数据回退说明：无法安全使用直接 SQL 处理或回退旧数据时，单独交付 `.txt` 或 `.md`。说明包括不适用 SQL 的原因、影响范围、备份或恢复来源、人工回退步骤和验证方式。能够用直接 SQL 完成的正向变更仍交付对应脚本。

没有 SQL/配置变更时不生成空文件。源码 XML、截图、测试程序、内部 JSON 校验清单、普通说明报告、菜单链接、License 申请不作为独立研发产物。菜单/权限说明仍保存在研发结果与验收项账本中。内部审计、构建和报告记录不删除。

## 收集与门禁

1. 项目预设和运行时策略统一允许 SQL、配置和旧数据回退说明。SQL 同时支持仓库根目录及多层目录。提交前、归集和上传时检查 SQL 正文，命中存储过程语句则阻止交付。
2. `delivery_assets` 按仓库和相对路径声明实际文件。SQL 和运行配置可自动识别，回退说明需显式声明。源码 XML、测试目录、构建输出与 secrets 不归集。已存在但本次实际使用的迁移也可明确声明，不必为收集而改写历史文件。
3. 本地打包、审核后本地打包、审核后流水线发版都执行归集。进入最终交付时再次核对；沿本任务保存的文件集合归集，不能把其他并发需求合入目标分支的文件混进来。
4. DM7 写入调用在开始/结束时保存任务级调用 ID、用途、状态和 SQL 指纹；不保存原始 SQL、连接 ID或凭据，不导出全局 DM7 发布日志。失败或继续执行后仍核对历史调用。命令行数据库操作也必须在结构化结果中如实声明并保存业务脚本。
5. `database_changes` 将调用映射到业务 SQL 或有清理/回滚证据的临时验证。缺文件、空文件、越界路径、遗漏脚本声明进入现有原会话自动补齐流程，不新增管理员常规确认。
6. 页面、交付记录、邮件和 TFS 交付清单使用同一可见范围。内部验证 JSON 保留审计但不展示。业务包缺失不能用 README 冒充成功。
7. 任务详情和交付记录可在线预览 SQL、TXT、YAML 等文本文件，沿用下载权限。预览显示前 512 KiB 的纯文本，原文件可下载。本地文件和有效的阿里云 OSS 文件链接均可预览。
8. 研发任务交付后可按需生成业务逻辑图。执行器根据当前交付记录调用原生 ImageGen，生成简短业务说明与流程图，加入任务交付产物。通知通过平台邮件配置发送给需求发起人和管理员，正文内嵌图片。

## 结果字段

`delivery_assets` 包含 `repository`、`path`、`kind`（`sql`、`config` 或 `rollback_note`）和 `purpose`。

`database_changes` 包含 `classification`（`business_change`、`temporary_verification` 或 `manual_rollback`）、`call_ids`、`script_paths` 和 `evidence`。多仓同名脚本应写仓库限定路径。临时验证须有清理或事务回滚证据。`manual_rollback` 的 `script_paths` 指向已声明的回退说明，`evidence` 记录使用人工回退的原因，已执行的业务写入仍需对应正式 SQL。

自动补齐只保存/修正脚本，不应再次执行已经完成的业务写入；数据库验证与实际部署仍遵循项目已有权限和交付流程。

历史上从未保存过的 SQL 无法凭空恢复；已归集但被审核模式隐藏的 SQL/配置会恢复显示。新任务执行完整性检查，继续中的旧任务在交付时补做文件归集。
